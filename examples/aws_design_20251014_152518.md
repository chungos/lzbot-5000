## Executive Summary

This design provides a comprehensive AWS CloudWAN-based network architecture spanning Melbourne (ap-southeast-2) and Sydney (ap-southeast-4) regions, specifically engineered to meet your requirements for:

- **Centralized Packet Inspection**: AWS Network Firewall in dedicated inspection VPCs
- **Decentralized Egress**: Regional NAT Gateways for optimal performance and cost
- **Centralized Ingress**: Application Load Balancers with CloudFront CDN
- **Network Segmentation**: Secure, Standard, and Web segments via CloudWAN policies
- **Low Latency**: Regional deployment with CloudFront edge optimization
- **Strong Security**: Defense-in-depth with WAF, Network Firewall, and segmentation
- **Predictable Costs**: Reserved capacity and optimized data transfer patterns

## Architecture Overview

### CloudWAN Core Network Design

Based on the [AWS CloudWAN documentation](https://docs.aws.amazon.com/whitepapers/latest/building-scalable-secure-multi-vpc-network-infrastructure/aws-cloud-wan.html), our design implements a **centralized policy-driven network** with three distinct segments:

1. **Secure Segment**: Houses inspection infrastructure and security services
2. **Web Segment**: Contains internet-facing web applications and load balancers  
3. **Standard Segment**: Hosts private application tiers and databases

### Regional Distribution

**Melbourne Region (ap-southeast-2) - Primary:**
- Primary RDS database with Multi-AZ deployment
- Centralized egress through inspection VPC
- Full application stack deployment

**Sydney Region (ap-southeast-4) - Secondary:**
- RDS read replica for disaster recovery
- Decentralized egress for improved performance
- Identical application stack for redundancy

### 3. Security Controls Implementation

#### Deep Packet Inspection
Following [AWS Well-Architected Framework SEC05-BP04](https://docs.aws.amazon.com/wellarchitected/2023-10-03/framework/sec_network_protection_inspection.html), we implement multi-layer inspection:

**AWS Network Firewall Rules:**
```yaml
StatefulRuleGroups:
  - RuleGroup: WebApplicationProtection
    Rules:
      - Block malicious IPs and domains
      - SQL injection prevention
      - Cross-site scripting protection
      - DDoS mitigation rules
  
  - RuleGroup: DatabaseProtection
    Rules:
      - Restrict database ports to application subnets
      - Monitor for data exfiltration patterns
      - Block unauthorized database access attempts
```

#### Web Application Firewall (WAF)
**Managed Rules Applied:**
- AWS Managed Rules Core Rule Set
- AWS Managed Rules Known Bad Inputs
- AWS Managed Rules SQL Database Protection
- AWS Managed Rules Linux Operating System
- Rate limiting: 2000 requests per 5-minute window per IP

```
Internet Users → CloudFront CDN → AWS WAF → CloudWAN Core → Regional ALBs → Web Servers

### 2. Centralized Packet Inspection
```
All Segments → CloudWAN Core → Secure Segment VPC → Network Firewall → NAT Gateway → Internet
```

### 3. Cross-Region Communication
```
Melbourne Apps ↔ CloudWAN Core ↔ Sydney Apps
Database Replication: Melbourne Primary → Sydney Read Replica

- Database replication lag
- Security event rates and patterns

**Automated Responses:**

### Disaster Recovery

**RTO**: 15 minutes (automated failover)
**RPO**: 5 minutes (database replication lag)

**Failover Process:**
1. Health checks detect Melbourne region failure
2. Route 53 DNS automatically redirects to Sydney
3. CloudFront origin switches to Sydney ALB
4. RDS read replica promoted to primary
5. Applications continue with minimal disruption
